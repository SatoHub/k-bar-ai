# 市場を「1つ抜く」予想システム 設計メモ

更新日: 2026-06-21
ステータス: 設計フェーズ（実装未着手）
関連: `docs/20260613-model-improvement-findings.md`（モデル改善の構造的頭打ち）、`docs/progress.md`

## 0. このメモの目的

2026-06-21 東京11R「府中牝馬S」でAI予想が大きく外れた事象を起点に、
**市場（オッズ・人気）を選択的に上回り、三連複・三連単のヒモ妙味馬を絞り込む**ための
開発方針を整理する。ユーザー要望は以下の3点:

1. 市場より1つ抜きん出た予想を立てられるようになりたい
2. 三連複・三連単で「来そうな馬」をある程度絞れるようになりたい
3. パドック映像から「来そうな馬」を見抜く観点を予想に組み込みたい

---

## 1. 事象分析: 2026-06-21 府中牝馬S（東京11R / 芝1800 / 16頭）

### 予想 vs 結果

| 着順 | 馬名 | 人気 | 単勝 | AIの予想順位 |
|---|---|---|---|---|
| 1着 | セキトバイースト | 5人気 | 9.4 | **4番手** |
| 2着 | ウイントワイライト | 9人気 | 22.7 | **9番手** |
| 3着 | ミアネーロ | 14人気 | 94.6 | **16番手（最下位評価）** |
| 4着 | マカナ | 10人気 | 24.6 | 8番手 |
| 5着 | コガネノソラ | 3人気 | 8.1 | 5番手 |

- AI本命2頭 = ヴァルキリーバース(1人気)・ニシノティアモ(2人気) は馬券圏外に崩壊。
- 三連単(7-2-4) **1,066,160円**、馬連(7-2) 13,070円の**大波乱**。
- ※結果はnetkeibaから取得。人気・オッズは本番DBと完全一致で確認済み。

### 外れた本質

1. **モデルは市場の写し**: AI予想順位 1〜5番手 = 人気 1,2,4,5,3 とほぼ人気順をなぞる。
   SHAP説明も全頭「単勝オッズ」「人気順」が支配的。**オッズと相関する情報しか持たない**ため、
   市場全体が間違える展開（人気馬飛び・人気薄好走）ではモデルも同じ間違い方をする。
   → `20260613-model-improvement-findings.md` の結論（同情報では市場を超えられない）の実例。

2. **勝ち馬自体は外していない**: 勝ったセキトバイーストはAI4番手で、複勝・単勝なら圏内。
   壊滅の正体は**ヒモ（2着9人気・3着14人気）**で連系（馬連・三連複・三連単）が崩れたこと。

3. **モデルは「分からない」と言っていた**: 全16頭 confidence:"low"、トップスコアも0.45どまり。
   = 実力拮抗＝荒れる余地大、という**未活用の警告サイン**が出ていた。

---

## 2. 基本戦略: 市場の「非効率な場所」だけを攻める

全レースで市場を上回るのは構造的に不可能（控除率20%＋公衆は強い）。
公衆が**最も正確なのは最上位の単勝確率**、**最もいい加減なのが中〜下位人気の連対・複勝力**。
エッジはそこにしか無い。よって「1つ抜く」を達成可能な3つの的に分解する:

1. **荒れるレースを当てる**（レース選択）
2. **荒れるレースでヒモ妙味馬を絞る**（6〜15人気の歪みを突く）
3. **危険な人気馬を消す**（1人気を切る判断）

狙いは「全部当てる」ではなく「**特定条件で選択的にプラス**」。

## 3. 実装ロードマップ

### Phase 1 — 既存データのみで即着手（新規データ不要・最安）

今回出ていた「low confidence＝荒れサイン」を製品化する。

- **荒れ度スコア（レース単位）**: 1人気の予想スコア／信頼度、予想スコアの分散、
  オッズ分散、頭数、コースから「波乱確率」を算出。本レースは赤信号が出るはず。
- **ヒモ妙味スコア（馬単位）**: **オッズ・人気を一切使わない特徴量のみ**で複勝/Top5確率を
  再学習し、`モデル評価 ≫ 人気順` の乖離が大きい馬＝**過小評価馬**を抽出。
  → 三連複/三連単のヒモ候補リスト。
- **危険人気馬フラグ**: 「人気だが非オッズ特徴が弱い」馬を消し候補化。
- **出力**: 荒れ判定時に「軸1頭（堅め）＋ヒモ広め」のフォーメーション・点数・予算を提案。
- **検証**: 「荒れ判定レース限定のROI」をバックテスト。**控除率20%を超えるかが最初の意思決定点**。
  （超えられない可能性も明記。その結果自体が次の判断材料）

### Phase 2 — レバーA: 情報エッジ取得（スクレイパー改修・中コスト）

Phase1のヒモスコアの"燃料"になる、市場が織り込みきれない情報を**現在レースでも**取得・特徴量化:

- **脚質・展開**（`corner_pos_1..4` は現状 null。過去データは100%保有）→ 前残り/差し有利の展開予測。
  今回の差し決着はここで示唆できた可能性。
- **当日の馬場バイアス**（含水率・クッション・内外有利。スクレイパー導入済み `app/scraper/jra_baba.py`）。
- **馬体重増減・乗り替わり**。
- **オッズ変動**（`odds_snapshots`: 直前に売れている/嫌われている妙味。現状は直近レースのみ）。

### Phase 3 — パドック映像分析（高コスト・本命の差別化）

**まず人間のチェックリストを手入力UIで予想に組み込み、効果を数値検証してからCV自動化に投資**する。

パドックで見るべきポイント（穴を拾う／人気馬を消す観点）:

| チェック項目 | 良い兆候 | 危険な兆候 |
|---|---|---|
| 毛艶 | ツヤがあり光る | くすむ・パサつき |
| 歩様（特にトモの踏み込み） | 大きくスムーズ、後肢が深く入る | 硬い・ぎこちない・かばう |
| 馬体（張り・余分な肉） | 適度な絞れ・筋肉の張り | 太め残り / 細すぎ |
| 発汗・気配 | 適度 | 大量発汗・チャカつき＝入れ込み（エネルギー浪費） |
| 落ち着き（耳・首・立ち上がり） | 耳が周囲に向き集中 | 首振り・立ち上がり・イレ込み |

- **自動化案**: キーフレーム → Claude Vision に上記ルーブリックで採点させ → 構造化スコア → 特徴量化。
  （本アプリのスタックと相性良。pose/keypointモデル併用も選択肢）
- **最大の壁**: 映像データの取得（ToS・保存）とラベリング。だから手入力で効果検証が先。
- ⚠️ **注意**: パドックの良し悪しは直前オッズに一部織り込まれる。
  単独より**オッズ変動（Phase2）と組み合わせて真価**が出る。

## 4. 正直な期待値（記録として残す）

- 控除率20%は重い。**「全部当てる」は目標にしない**。
- まず Phase1 のバックテストで「荒れ判定×ヒモ戦略」が控除率を超えるか数字で見極める。
- 超えられない結果もあり得るが、それが分かること自体が意思決定の前進。
- モデル単体の精度向上は頭打ち（既存検証済み）。勝ち筋は**情報エッジ（レバーA／パドック）**の追加のみ。

## 5. Phase 1 実行結果（2026-06-21・バックテスト実施済み）

実装: `backend/app/ml/oddsfree.py`（オッズ非依存モデル）、`backend/scripts/phase1_edge_backtest.py`。
検証: ローカルDB全履歴161万件、train<2020 / test>=2020（5,563レース）。

### 結果A: 荒れ度スコア = ✅ 有効
- **upset_score AUC = 0.654**（荒れ=「1人気が複勝圏外」、base rate 36.3%）。modestだが実用域。
- **decile校正が綺麗に単調**: 最下位D1=実荒れ率18.3% → 最上位D10=57.8%。
  D10は top3 の平均最低人気=8.9（人気薄が絡む）。
- **最強の荒れ予測因子 = `max_p_main`（係数 -0.925）**。
  = 本モデルの最高スコアが低い（＝全頭low confidence）レースほど荒れる。
  → 6/21府中牝馬S（max予想スコア0.45・全頭low）が大荒れだった事実と完全に一致。
  次点 `pmain_entropy(+0.276)` も同方向（予想が割れる＝荒れる）。
- **結論**: 「どのレースが荒れるか」は既存データだけで当てられる。
  荒れ度スコアは製品化の価値あり（馬券戦略の切替トリガー）。

### 結果B: ヒモ妙味（オッズ非依存） = ❌ naiveに敗北
荒れ判定レース上位30%（1,669R）で、軸=人気1,2＋ヒモ6頭の三連複ボックス的中率:
- **妙味(oddsfree)選択: 15.2%（254/1669）**
- **人気順naive選択（人気3-8）: 56.7%（947/1669）** ← naiveが圧勝
- 人気薄(6人気以下)で実際3着内に来た馬の捕捉率も oddsfree 52.8% vs naive 54.2% でnaive優位。

**解釈**: オッズを無視してmyoumi最大で選ぶと、市場が正しく見限った弱い馬を拾ってしまい、
現実の好走ゾーン（人気3-8）を取りこぼす。**複勝市場は十分に効率的**で、
新情報なしに「オッズ非依存スコア」で市場を上回ることはできない。
→ `20260613-model-improvement-findings.md`「同情報では市場を超えられない」「EV戦略は穴馬過大評価で大負け」の再確認。

### Phase 1 の決定的な学び
1. **荒れ検知は安価に達成可能**（既存データのみ）。→ すぐ製品化してよい。
2. **ヒモ妙味の安価版（オッズ無視）は無価値**。ヒモ選択は素直に人気順（人気1-8ボックス）が最善。
3. → **ヒモ精度を上げる唯一の道は Phase 2 の情報エッジ**（脚質/展開・馬場バイアス・オッズ変動）。
   市場が持たない情報を足さない限り、ヒモで市場は抜けない。Phase 2 への投資が正当化された。

## 6. Phase 1 製品化（2026-06-21 完了・検証済み）

荒れ度スコアをアプリに統合。**新テーブル/マイグレーション不要**（予想生成時に揃う
win_odds/win_favorite＋p_main から API応答時に算出）。
- 学習済みartifact: `backend/models/upset_score.joblib`（StandardScaler+LogisticRegression, AUC0.654）。
  学習/推論=`backend/app/ml/upset_score.py`（`train_and_save()` / `score_race()`）。
- Backend: `prediction_service.get_race_predictions` が `upset`(score/percentile/level/hint) を返す。
  スキーマ=`app/schemas/prediction.py::UpsetScore`。
- Frontend: `PredictionTable` に荒れ度バナー（高/中/低＋波乱確率＋戦略ヒント）。型=`api.ts::UpsetScore`。
- 検証: 6/21府中牝馬S → **荒れ度 high・波乱69%・上位1%**（あの大荒れを事前警告できた）。
  実DBレース → mid。型チェック・サービスimport・E2E(get_race_predictions)すべて通過。
- ⚠️ 本番反映は未実施（VPSへ `upset_score.joblib` 転送＋push が必要・ユーザー判断待ち）。

## 7. Phase 2 検証結果（2026-06-21・脚質/展開 = ✅ 有効）

実装: `backend/scripts/phase2_pace_backtest.py`。`corner_pos_4`(最終コーナー順・2012-2021は100%)から
**leak-freeな脚質(horse_style)・展開(race_n_front, race_pace_pressure, style_vs_pace)** を生成し、
odds非依存モデルに追加。荒れ判定上位30%(1,669R)で3つのヒモ選択を比較:

| ヒモ選択手法 | 三連複box的中 | 人気薄(6人気↓)捕捉 |
|---|---|---|
| naive (人気3-8) | **56.7%** | 54.2% |
| oddsfree (脚質なし=Phase1) | 15.2% | 52.8% |
| oddsfree + 脚質/展開 | 16.6% | 54.6% |
| **+脚質/展開 (人気≤10限定)** | 32.5% | **69.4%** |

- **決定的: 脚質/展開＋人気≤10の限定で、人気薄好走馬(6人気以下で3着内)の捕捉率が 54%→69%(+15pt)。**
  = 府中牝馬Sの9人気・14人気のような「市場が見落とす穴」を、市場より明確に拾える。
- 最重要特徴量 = `style_vs_pace`（速い展開での差し馬の利、gain圧倒的1位）→ **展開は市場が織り込めていない実エッジ**。
- 注意: 三連複box全体ではnaive(人気1-8)が依然優位（軽い荒れは人気内で収まるため）。
  → 正しい買い方は「堅い軸(人気)＋脚質/展開で選んだ穴ヒモ」の併用。ROI(円)は払戻データ不足で未算出。
- **結論: Phase1の安価版と違い、脚質/展開は本物の情報エッジ。スクレイパー投資が正当化された。**
