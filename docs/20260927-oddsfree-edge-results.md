# オッズ非依存モデルで市場に勝てるか → **見込みなし**（2026-09-27 実測）

判定基準は測定前に `20260927-oddsfree-edge-criteria.md` で確定させた。以後緩めていない。
再現: `cd backend && PYTHONPATH=. uv run python scripts/oddsfree_edge_eval.py --measure-skew`

## 結論

**単勝で「モデルが市場より高く評価している馬」を買う戦略は、有意に赤字。**
50,398点・ROI **72.7%**・95%CI **[66.5%, 79.2%]** → **CI 上限が 100% を下回る**。
「判定不能」ではなく**否定が確定した**（事前登録 §2 の「見込みなし」）。

キャリブレーションは崩れていない（下記）。**つまり「確率が歪んでいるから負けた」のではなく、
確率は正しいのに市場より情報が少ない**、という負け方である。

### 🔴 AUC 0.733 はリークによる水増しではなく、バグによる**目減り**だった

| モデル | target | AUC |
|---|---|---|
| `v1.0.0_oddsfree`（バグ修正前・記録値） | is_place | 0.73335 |
| **`v1.2.0_oddsfree`（修正後）** | is_place | **0.74819** |
| **`v1.2.0_win_oddsfree`（修正後）** | is_win | **0.75868** |

同じ目的変数で **0.733 → 0.748（+0.015）**。壊れた集計特徴量は精度を*下げて*いた。
「未来情報リークで 0.733 が下駄を履いている」という私の当初の懸念は**否定された**。

## キャリブレーション（EV 判定の前提）— 合格

| | ECE | Brier | 有効ビン |
|---|---|---|---|
| モデル（生の出力） | 0.0041 | 0.06246 | 10/10 |
| モデル（レース内正規化） | 0.0027 | 0.06155 | 10/10 |
| **市場（オッズ→勝率）** | **0.0015** | **0.05796** | 10/10 |

許容 0.02 に対し**両方とも十分小さい**（ゲートは生と正規化後の厳しい方で判定）。
モデルが「勝率10%」と言った馬はおよそ 10% 勝っている（最大のずれは最上位ビンの 1.2pp）。

**ただし市場のほうが ECE も Brier も良い。** Brier は「確率の当たり具合」の総合点で、
小さいほど良い。0.05796 < 0.06155 なので**市場の確率のほうが一貫して精度が高い**。

## 単勝 ROI（フラットベット・確定オッズ・OOS 2020年以降）

| 買い方 | 点数 | 的中 | ROI | 95%CI | 平均オッズ | 判定 |
|---|---|---|---|---|---|---|
| 全馬均等 | 77,614 | 7.2% | 75.2% | [71.0, 79.6] | 63.0倍 | 見込みなし |
| **1番人気** | 5,585 | 32.6% | **79.8%** | [76.6, 83.0] | 2.7倍 | 見込みなし |
| 市場最上位1頭 | 5,585 | 32.4% | 79.1% | [75.9, 82.4] | 2.7倍 | 見込みなし |
| モデル最上位1頭 | 5,585 | 24.9% | 73.1% | [68.8, 77.6] | 4.8倍 | 見込みなし |
| **🔴 主判定 妙味馬 edge>0** | **50,398** | **3.6%** | **72.7%** | **[66.5, 79.2]** | **84.3倍** | **見込みなし** |

探索（判定根拠にしない）: edge 閾値 0.01〜0.10 は 61〜76%、EV>1.0〜1.5 は 72〜73%、
オッズ帯別は 69〜84%、**100% を超えたものは1つも無い**。

### 負けている仕組み

**妙味馬の平均オッズが 84.3倍。** モデルは体系的に人気薄を「買い」と判定している。
理由は情報ではなく**解像度の低さ**である。モデルは市場より Brier が悪い＝予測が平板で、
人気馬に市場ほど高い確率を置けず、人気薄に市場より高い確率を置く。
レース内で合計1に正規化すると、その差が「人気薄に妙味あり」として大量に出る。
そして人気薄は実際には過剰に買われている（下記）ので、買えば負ける。

- `Σ(1/オッズ)` のレース平均 **1.2529** → 控除率 **20.18%**（JRA公式 単勝20%と一致）
  → `race_entries.win_odds` が確定オッズ＝払戻の基準であることの実証
- 全馬均等買いの実測 **75.2%**。控除率から期待される 79.8% より**低い**
  → **人気薄が過剰に買われている**（favourite-longshot bias）の実測。
    穴狙いは出発点で 4.6pp 不利

### 🔴 「1番人気 106.6%」は完全にノイズだった

同日、113レースで測った 1番人気の ROI は 106.6% だった。5,585レースで測り直すと
**79.8%・CI [76.6, 83.0]**。理論値 79.8%（=1/1.2529）と小数第1位まで一致する。
**事前登録した基準がこの罠を正しく弾いた**ことの実例:

```
2025年 edge>0   341点  ROI 133.8%  CI[37.3, 266.8]  必要 45,877点  → 判定不能
```

ROI が 133.8% でも、CI 幅が 230pp では何も言えない。
月別21区間でも ROI 中央値 70.9% / 100%超は 1区間のみ。

## 評価の妥当性について自分で確認したこと

| 項目 | 結果 |
|---|---|
| 学習期間の混入 | 無し。学習 `year < 2020` / 評価 `year >= 2020`。artifact の `cutoff_year` を照合して再利用 |
| 非完走馬（競走中止） | **ハズレとして計上**（363頭）。落とすと ROI が +0.37pp 楽観に歪むことを実測。出走取消・除外（返還）はオッズ無しで自然に除外（247頭） |
| 特徴量スキュー | 評価行列を `include_upcoming=True` で作ったことによる予測のずれを実測: 平均 0.00024 / p99 0.0055 / 最大 0.265 / 0.01超は 471行（0.6%）。**結論を動かす規模ではない** |
| 市場確率の復元方法 | レース内正規化と takeout 近似の両方で測り、ROI は 72.7% で一致 |
| 多重比較 | 主判定の閾値を事前に1つ指定。探索行は verdict を表示しない（境界では1行 2.7% で偽陽性が出るため） |

## 限界（結論を鵜呑みにしないための明記）

- **確定オッズで採点している。** 実際に賭ける時点では確定オッズは分からないので、
  ここで測った ROI は**現実より楽観的**。エッジが出ていたとしても締切前オッズでの再検証が必要だった
- OOS が 2020年〜2021年半ばに偏っている（2025/2026 は各数百点のみ）
- 複勝・ワイド・三連複は**払戻オッズが DB に無く評価不能**。単勝での否定が
  他券種にそのまま及ぶとは言えない（**未確認**）
- 手数料・最低賭け単位・資金制約は考慮していない

## 次に効く可能性が残るもの（この結果から言えること）

「オッズ非依存モデル単体で妙味馬を拾う」方向は**閉じた**。残るのは:

1. **市場が知らない情報を入れる**（`docs/20260613-model-improvement-findings.md` レバーA）。
   `corner_pos_1..4` が直近0%・`odds_snapshots` が直近レースのみ という**データ側の穴**を埋める。
   モデルの解像度が市場を下回っている以上、アルゴリズムではなく入力を増やすしかない
2. **締切前オッズの時系列**（`odds_snapshots` の蓄積）。確定オッズとの乖離＝直前の資金の動きは
   市場自身の情報で、モデルが今持っていない
3. **単勝以外**。ただし払戻データの整備が前提

⚠️ 1〜3 のいずれも「やれば勝てる」根拠は無い。**控除率20%を超えるのは
構造的に難しい**という事実は変わらない。

## 手法上の教訓: **判定基準を測る前に決めたことが効いた**

これは結果より再利用価値が高いので独立させて残す。

### 何が起きたか

同日、113レースで 1番人気の ROI を測って **106.6%** という数字が出た。控除率20%の単勝で
長期 106.6% はあり得ないのに、一瞬「市場が AI に勝っている」と読みかけた。
5,585レースで測り直したら **79.8%**（理論値 1/1.2529 = 79.8% と一致）。**完全なノイズだった。**

そこで**測定前に**基準を文書化して commit した（`920d41a`）。その効果:

```
2025年 edge>0    341点  ROI 133.8%  CI[37.3, 266.8]  必要45,877点  → 判定不能
```

**ROI 133.8% を「判定不能」と切れた。** 基準が後出しなら、ここを「有望」と読んでいた。
測ってから基準を作ると、出た数字に合わせて基準が動く。

### 具体的に効いた4点

1. **必要点数を「点数」ではなく「精度要件」で決めた。** 単勝1点の収支の sd は
   オッズ帯で 1.08〜8.66 と 65倍違う（実測）。「何点あればいい」は一律に決められない。
   → CI 半幅 ≤ 0.10 という精度要件にし、実測 sd から必要Nを逆算する形にした
2. **損益分岐を 1.00 と明記した。** 控除率 0.80 は「無策の期待値」であって分岐点ではない。
   同日これを取り違えたコードを書き、レビュー3件が独立に指摘した
3. **主判定の閾値を1つだけ事前指定した。** 閾値を20本試せば、境界では1行あたり
   約2.7%の確率で偽の「見込みあり」が出る（実測）。20本なら3〜4割で誰かが当たる。
   → 探索行は verdict を表示しない実装にした
4. **CI は bootstrap を主にした。** 単勝の払戻は裾が重く、正規近似は端で信用できない

### 併せて: 「直したと書いたのに直っていなかった」が2件あった

- `calibration` の異常系: 「異常系が『問題なし』として通過する欠陥を修正した」と
  コミットに書いたが、**定数を吐くモデルは ECE=0.0 / OK で通過していた**（実測）。
  KeyError を消しただけで意味論は未修正だった
- 予測時の特徴量列: artifact に保存した列ではなく現在の列定義を使っていた。
  LightGBM は列名を検証せず並べ替えもしない（**列順を変えると予測値が最大 0.869 変わる**）

いずれも独立レビューが実測で見つけた。**自分のコミットメッセージを検証の代わりにしない。**
これは `~/.claude/CLAUDE.md` §12.2-11（コメントを検証の代わりにしない）と同じ構造の失敗。

### 今回入れた防御は mutation testing で検出を実証した

判定順序の入替え / ECE の重み付け除去 / bootstrap を50%区間に / degenerate 無視
の4種を実際にコードへ入れ、**いずれも新テストが落ちることを確認**した（原状復帰済み）。
「テストがある」ではなく「テストが落ちる」を確認する。

## ⚠️ 何を否定できて、何を否定できていないか（範囲を厳密に）

`docs/progress.md` の課題 ⭐🔵 #6（Benter方式で控除率超えの可否を決着させる）は
①〜⑤の手順を挙げている。**今回やったのは ①②④⑤ で、③は未実施。**

| 手順 | 内容 | 今回 |
|---|---|---|
| ① | オッズ非依存の実力モデル `P_fund` | ✅ 実施（`v1.2.0_win_oddsfree`, AUC 0.759） |
| ② | オッズから市場勝率 `P_market`（レース内正規化） | ✅ 実施（控除率 20.18% を実証） |
| ③ | **メタモデル**: `勝敗 ~ logit(P_fund) + logit(P_market)` をロジスティック回帰で学習し**重みを最適化** | ❌ **未実施** |
| ④ | 合成確率が `P_market` を上回る馬を妙味として ROI をバックテスト | 🔶 **合成せず素朴な差分で実施** |
| ⑤ | 控除率超えのセグメントが無いか確認 | ✅ 実施（オッズ帯・年別・月別いずれも無し） |

### 🔴 したがって「閉じた」のは次の1つだけ

> **`P_fund − P_market > 0` の馬を買う（素朴な差分による妙味判定）は有意に赤字。**

**③のメタモデルは否定していない。** Benter 方式の要点はまさに「2つの確率を*どの重みで*混ぜるか
をデータから学ぶ」ことであり、今回の「差が正なら買う」は重みを 1:−1 に固定した特殊ケースに過ぎない。
今回の結果はむしろ③が必要な理由を示している:

- モデルの Brier（0.06155）は市場（0.05796）より**悪い**
  → モデルに市場と同じ重みを与えるのは過大評価。**重みを下げるべき**という示唆
- それでもモデルはキャリブレーションが取れており（ECE 0.0027）、AUC 0.759 で
  ランダム（0.5）から大きく離れている → **情報はゼロではない**
- 素朴な差分は「解像度の低さ」をそのままエッジと誤読した（平均オッズ 84.3倍の人気薄に偏った）。
  重みを学習すれば、この偏りは原理的に抑えられる

**ただし「③をやれば勝てる」とは言えない。** 控除率20%は依然として大きな壁で、
③で得られる改善が壁を超える保証は無い（**未検証・推測**）。

### 次に③をやる場合の注意（今回の測定から分かったこと）

- **重みの学習は 2019年以前だけで行う。** 2020年以降を使うと OOS が無くなる
- 合成確率も**レース内で正規化**して合計1にする（今回と同じ）
- 判定基準は `20260927-oddsfree-edge-criteria.md` をそのまま使える。
  **基準を作り直さない**（③に都合のいい基準を後から作ることになる）
- ケリー基準は**キャリブレーションが合成後も保たれていることを確認してから**。
  確率の誤差が賭け金に増幅されるため、まずフラットで測る
