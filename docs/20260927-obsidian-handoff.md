```markdown
# K-Bar AI — 競馬AI予想アプリ（2026-02 〜 2026-09・完了）

## 一行で
競馬の着順を予測する AI を作って本番7ヶ月運用し、**「賭けて勝てる見込みは無い」と
統計的に確定させて区切った**プロジェクト。

## 作ったもの
Next.js 15 / React 19 / Tailwind 4 + FastAPI / SQLAlchemy async + PostgreSQL 16 +
LightGBM(+SHAP) / Playwright スクレイピング / Docker Compose / ConoHa VPS /
nginx + **Let's Encrypt IPアドレス証明書**（ドメイン無しHTTPS）/ GitHub Actions 自動デプロイ /
systemd timer / APScheduler（ジョブ13個）/ LINE Messaging API 通知

## 規模（実測）
- 学習データ **161万件**（1986〜2021）
- 本番稼働 **約7ヶ月**・自動生成した予想 **29,072件**
- 締切前オッズ **510,108行 / 2,123レース**（1レース18スナップショット）
- テスト 182件・ruff clean・落ちたのは 502 が1回だけ

## 結論
- モデルの ROC-AUC は **0.811**。しかし**オッズ2特徴量をシャッフルすると 0.5068
  （ほぼコイン投げ）に落ちる** → モデルは実質「単勝オッズの言い換え」だった
- `win_odds` 単独の寄与 +0.245 に対し、**残り40特徴量の合計は +0.008 未満**
- 3つの角度すべてで否定:
  1. 妙味馬戦略 = 50,398点 **ROI 72.7% CI[66.5, 79.2]** → 有意に赤字
  2. Benter流二段モデル = **α=−0.0580 p=0.0714 CI[−0.121,+0.005]** → 市場に情報を
     足せていることを示せなかった（効果量の上限は市場の寄与の0.6%）
  3. 特徴量バグ修正後の再学習 = AUC が小数第4位まで同一

## 副産物: 市場の効率性の実測
- `Σ(1/オッズ)` = 1.2529 → 控除率 **20.18%**（JRA公式と一致）
- 全馬均等買い ROI **75.2%**（控除率から期待の79.8%より低い = **人気薄が過剰に買われている**）
- 1番人気の単勝 ROI **79.8%**（理論値と一致）

## 自己評価
**一番の成果は「やめる判断を数字で出せたこと」。**
やり直すなら **最初に「オッズを外したらどうなるか」を測る**。1日でできたし、
やっていればモデル改良の大半は不要だった。AUC ではなく ROI から始めるべきだった。

関連: [[検証の作法 — 測る前に基準を決める]] / [[動いているように見えて壊れていたもの]]
```

### ノート2: 「検証の作法 — 測る前に基準を決める」

**これが一番転用価値が高い。** 競馬と無関係に使える。

```markdown
# 検証の作法 — 測る前に基準を決める

## なぜ
113レースで測った ROI が **106.6%** で、一瞬「勝てている」と読みかけた。
5,585レースで測り直したら **79.8%**（理論値と一致）＝**完全なノイズ**だった。

## 効いた4点
1. **測る前に判定基準を文書化して commit する。**
   後から決めると出た数字に合わせて基準が動く。
   実例: `341点 ROI 133.8% CI[37.3, 266.8] 必要45,877点 → 判定不能` と切れた。
   後出しなら「有望」と読んでいた
2. **必要サンプル数を分散から逆算する。** 賭け1点の収支の sd は
   オッズ帯で **1.08〜8.66** = 必要点数が **446〜28,803点で65倍違う**。
   「何件あれば信じていいか」を感覚で決めてはいけない。
   → 点数を固定せず **精度要件（CI半幅≤0.10）＋絶対下限（N≥500）** にする
3. **多重比較を先に潰す。** 閾値を20本試せば境界では1本あたり約2.7%で
   偽の「有望」が出る＝**20本なら3〜4割でどれかが当たる**。
   主判定の閾値を1つだけ事前指定し、残りは verdict を表示しない
4. **裾が重い分布に正規近似を使わない。** CI は bootstrap を主にする

## 「示せなかった」と「無いと示された」を書き分ける
帰無仮説を棄却できないことは帰無仮説の証明ではない。
事前に等価性マージンを登録していないなら、言えるのは**効果量の上限**だけ。

## テストが機能するかを検証する（mutation testing）
「テストがある」ではなく「**テストが落ちる**」を確認する。
実例: **p値を片側化（=有意水準を2倍にするのと同じ）しても27件全部通った。**
原因は偽陽性率テストの検出力不足で、**真の偽陽性率が2倍に悪化しても検出確率4.3%**だった。
→ **確率的な検定のテストは、検出力を計算してから書く。**

## レビューは複数回す（実績ベース）
- **別モデル（Codex）**: 診断コードが学習成果を消す P1、guard hook が PowerShell を素通り、
  「棄却できない」を「無い」と断定する推論の誤り
- `code-reviewer`: 予測時に artifact の特徴量列を使っていない（列順違いで予測が最大0.869変わる）
- `security-reviewer`: 定数を吐くモデルが「キャリブレーションOK」で通過
- `test-reviewer`: mutation testing でテストの穴を**定量的に**実証

**同じモデルのレビュアー同士は同じ勘違いをする。**
一方 **レビューも鵜呑みにしない** — 75通り探して0件だった指摘はコードではなく
テストの前提が誤っていたので、テスト側を直した。
```

### ノート3: 「動いているように見えて壊れていたもの」

```markdown
# 動いているように見えて壊れていたもの（K-Bar AI で実際に見つけた12件）

## データ処理
- **pandas: `grouped[col].shift(1)` は素の Series を返す。**
  そこに `.rolling()` / `.expanding()` をかけると窓がグループ境界をまたぐ。
  → 集計特徴量24個が別の馬・別の騎手の値を拾っていた。12個は全行汚染で、
  騎手の通算勝率が「データ全体の累積平均」になっていた。**未来情報リークにもなっていた**
  - **なぜ気づけなかったか**: リーク検査テストは既にあったが全て `n_horses=1`。
    **バグは「別のエンティティの値を拾う」ものなので、エンティティが1つでは構造的に検出不能**
- 検証用分割が `iloc[:90%]` の位置ベースで、並び順がエンティティ順だったため
  「時系列の後ろ10%」ではなく「特定の馬の集まり」になっていた

## 評価・金銭計算
- **ROI の損益分岐は 1.00。控除率 0.80 は「無策の期待値」であって分岐点ではない**
  → 0.80 を分岐点にすると赤字を黒字と読む
- 未確定レースを「賭けてハズレ」として集計していた（オッズは結果より先に入る）
- **診断コードが学習成果を消していた**（dtype 破壊で例外 → artifact 保存の前なので
  数十分の学習が消える）

## インフラ
- **nginx の `upstream { server name:port }` は起動時に1度だけ名前解決する**
  （`resolve` は nginx Plus 限定）。コンテナ再作成で IP が入れ替わり全ページ 502。
  **IP が偶然同じなら起きないので発覚は運任せ**
- **`nginx -s reload` は非同期。** 古い worker がメモリ上の旧証明書を配り続ける
  （実測: 6秒後もまだ旧証明書）→ reload 直後に読むと誤判定する
- **`.htpasswd` を 640 にすると worker が読めないが、未認証には 401 を返すので
  一見正常。** 正しいパスワードを入れた人だけが 500 を食らう
- **systemd の `OnFailure=` は `[Unit]` のディレクティブ。`[Service]` に書くと
  エラーも出さず黙って無視される**
- ヘルスチェックの `curl -sf` は **3xx を成功扱い**。HTTPS化で302を返すようになった
  後はアップストリームが死んでいても「正常」と報告していた
- Windows の git は実行ビットを記録しないので systemd が `203/EXEC` になる。
  `.gitattributes eol=lf` は git 経由のチェックアウトしか守らない（tar 転送でCRLF混入）

## 安全機構そのもの
- guard hook の fail-open: ①Bash だけ見て PowerShell を素通り
  ②**正規表現1つが壊れると例外でループを抜けて全ルートが無効化**
  ③ヒアドキュメント内を未検査
  → **変更規模は設定ファイル1つだったが、中身は全ての防御を無効化する穴。
  危険さと差分の大きさは相関しない**
- post-edit hook の失敗結果が `systemMessage` にしか出ず、AI 側に届いていなかった
  （人間には見えるので「動いている」ように見えた）

## 🔴 共通する原因
**コメント・関数名・自分のコミットメッセージを、検証の代わりにしていた。**
- `"prevent future data leakage"` というコメント → 実際は壊れていた
- nginx の「流量を絞る」というコメント → `limit_req` は1件も存在しなかった
- 「異常系を修正した」というコミットメッセージ → 実際は通過していた
- **自分が追加したテストが無検査だった**（`pytest.approx` の既定の絶対許容 1e-12 が
  p≈1e-133 を無条件に一致させ、片側化しても通っていた）

→ **防御していると書いてあるのが一番危険。レビュー時に「対策済み」と誤認させる。**
```
