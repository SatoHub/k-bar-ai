# 「オッズ非依存モデルで市場に勝てるか」の判定基準（事前登録）

作成: 2026-09-27 / **測定前に確定させた。以後この基準を後から緩めない。**

## なぜ先に決めるのか

同日、単勝ROIを 113点で測って「1番人気 106.6%」という数字が出た。控除率20%の
単勝で長期 106.6% はあり得ないので、これは**ノイズを実力と読み違える罠**の実例である。
測ってから基準を作ると、出た数字に合わせて基準が動く。だから先に書いて commit する。

---

## 1. 何点あれば ROI を信じてよいか

### 素朴な二項近似では足りない

単勝の1点あたり収支は `X = オッズ × 当たり(0/1)`。的中率だけを見る二項近似は
`sd ≈ 0.5` 程度だが、**実際の X は払戻が跳ねるので裾が重い。**
2020年以降の実データ（77,251点）で実測した:

| オッズ帯 | 点数 | 平均X | **sd(X)** | CI半幅0.10に必要なN |
|---|---|---|---|---|
| 1〜3倍 | 3,937 | 0.803 | 1.078 | **446** |
| 3〜6倍 | 9,702 | 0.803 | 1.697 | **1,106** |
| 6〜12倍 | 11,924 | 0.775 | 2.447 | **2,301** |
| 12〜30倍 | 17,260 | 0.847 | 3.969 | **6,051** |
| 30倍以上 | 34,428 | 0.685 | 8.659 | **28,803** |
| 全体 | 77,251 | 0.756 | 6.187 | 14,707 |

必要N = `(1.96 × sd / 0.10)^2`（95%CI の半幅を ROI 10ポイント以内にする）。

🔴 **この表が一番重要な事前知識である。** 買う馬のオッズ帯で必要点数が **65倍** 違う。
人気薄を買う戦略は、**手元の全データ（5,585レース）を使っても構造的に判定不能**。
「穴で高ROIが出た」は、ほぼ必ずノイズである。

### 採用する手続き

1. ROI の 95% CI は **bootstrap（resample with replacement, 10,000回）** で出す。
   裾が重く正規近似が信用できないため。正規近似 SE も併記し、乖離すれば bootstrap を採る。
2. **必要点数は固定値で決めず、精度要件で決める。**
   - 要件: **95% CI の半幅 ≤ 0.10**
   - かつ **絶対下限 N ≥ 500 点**（どれだけ sd が小さくても下回ったら判定しない）
3. 実測 sd から必要Nを逆算し、満たさなければ **点数不足＝判定不能**。

## 2. 判定の境界値

損益分岐は **ROI = 1.00**（控除率 0.80 は「無策で賭けた時の期待値」であって分岐点ではない。
同日この取り違えをレビュー3件で指摘された）。

| 判定 | 条件 |
|---|---|
| **見込みあり** | CI 下限 > 1.00 **かつ** 精度要件（§1-2）を満たす |
| **見込みなし** | CI 上限 < 1.00 **かつ** 精度要件を満たす（＝有意に赤字） |
| **判定不能** | 上記以外（CI が 1.00 をまたぐ / 点数不足） |

🔴 **ROI が 100% を超えていても、精度要件を満たさなければ「判定不能」と言う。**
「見込みあり」と書けるのは CI 下限が 1.00 を超えた時だけ。

### 多重比較の扱い

閾値を何通りも試せば、最良の閾値の ROI は必ず上振れする（選択バイアス）。
そこで **主判定の閾値を1つだけ事前に指定する**:

> **主判定 = 「モデル確率 > 市場確率」の馬すべてを均等に単勝で買う（edge > 0）。**

他の閾値（edge ≥ 5%, 10%, …、オッズ帯別）は**探索として報告**し、
そこで良い数字が出ても「見込みあり」の根拠には**しない**。

## 3. キャリブレーション要件（EV戦略の前提）

EV（期待値）判定は「モデルの確率が確率として正しい」ことに依存する。
モデルが「勝率20%」と言った馬が実際に20%勝っていなければ、EV の計算自体が無意味。

- **信頼度曲線**（予測確率を10分位に区切り、各ビンの予測平均 vs 実測勝率）を出す
- **ECE**（Expected Calibration Error, 各ビンの |予測-実測| を件数で重み付け平均）
- **Brier score**
- 判定: **ECE > 0.02 なら「EVベースの戦略は現状成立しない」と結論する。**
  根拠: 単勝の主戦場は勝率 5〜30% 帯で、そこで狙うエッジは数ポイント規模。
  確率の系統誤差が 2ポイントを超えると、エッジがすべて誤差に埋もれる。
- キャリブレーションが崩れている場合、**それ自体が結論**であり、
  ROI が良く見えても採用しない（等温回帰などの補正は「次に作るもの」の候補に回す）。

## 4. 評価の設計

| 項目 | 決定 | 理由 |
|---|---|---|
| 馬券種 | **単勝のみ** | 払戻が単一オッズで決まる。複勝は払戻オッズが DB に無く**計算不能**（推測で埋めない） |
| ベット額 | **フラット（均等）** | Kelly は「真の確率が既知」を前提にする。キャリブレーション未検証の段階で使うと、確率の誤差が賭け金に増幅されて ROI 推定が壊れる。まずフラットで「エッジの有無」だけを見る |
| 期間 | **2020-01-01 以降のみ**（out-of-sample） | 学習は 2019年以前（`cutoff_year=2020`）。手元の 2020年以降は 5,585レース / 77,251点 |
| 時系列 | 年別・月別にも ROI を出す | 全期間の平均が1つの時期に支えられていないか確認する |
| 市場確率 | ①`0.7982/O`（控除率実測値）と ②**レース内正規化** `(1/O)/Σ(1/O)` の両方 | ②が本筋（オーバーラウンドを正しく除去）。①も併記して差を見る |
| モデル確率 | 生の値とレース内正規化の両方 | 二値分類の出力はレース内で合計1にならないため |
| ベースライン | (a) 全馬均等 (b) 1番人気 — **同一期間・同一集合** | 比較対象がないと「良い」が判定できない |

### 実測した市場の性質（前提確認）

- `Σ(1/オッズ)` のレース平均 = **1.2529** → **控除率 20.18%**（JRA公式 単勝20% と一致）
  → **`race_entries.win_odds` は確定オッズ＝払戻の基準**であることが実証された
- 全馬均等買いの実測 ROI = **0.7557**。控除率から期待される 0.798 より**低い**
  → **人気薄が過剰に買われている**（favourite-longshot bias）の実測。頭数の多い人気薄側に
    均等配分が引っ張られるため。**穴狙いは出発点で不利**という定量的な裏付け

## 5. 🔴 既存 `v1.0.0_oddsfree` をそのまま評価できない理由

当初の方針は「既存モデルで見極める」だったが、**そのままでは無効**。測定前に判明した:

1. **学習日が 2026-06-21 で、特徴量バグ修正（2026-09-27）より前。**
   39特徴量すべてが「別エンティティの値を拾う」実装で計算されていた。
   しかも `expanding` は並び順の先頭から累積するため、**2020年以降のレースが
   2019年以前の学習行に混入**していた（未来情報リーク）。
   → **AUC 0.733 は水増しの可能性がある。今の特徴量で採点すると学習時と意味が違う。**
2. **目的変数が `is_place`（3着内）なのに、評価したいのは単勝。**
   複勝の払戻オッズは DB に無い。単勝オッズと突き合わせるには
   目的変数が `is_win` でなければ確率の意味が合わない。
3. 検証分割が `iloc[:90%]` の位置ベース（`trainer.py` で同じ欠陥を修正済み）。

→ **修正後の特徴量で `is_win` を目的変数に再学習**したモデルで評価する。
これは「新しく作り込む」ではなく、**測定を成立させるための最小条件**。
参考として `is_place` 版も修正後特徴量で再学習し、**0.733 がリーク由来だったかを切り分ける**。

## 6. この評価の限界（先に明記しておく）

- **確定オッズで採点している。** 実際に賭ける時点では確定オッズは分からない。
  したがって**測定される ROI は現実より楽観的**。エッジが見つかっても、
  締切前オッズでの再検証が必須になる（`odds_snapshots` が直近レースのみという穴）。
- OOS 期間が 2020年〜2021年半ばに偏っている（2021は途中まで）。
  レース傾向の時代変化に対する頑健性は測れない。
- 手数料・馬券の最低単位・資金制約は考慮しない（エッジの有無だけを見る段階）。
