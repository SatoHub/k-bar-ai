# モデル精度向上の検証結果（2026-06-13）

予測スコア改良の依頼を受けて、複数の改良案を**厳密に検証**した記録。
結論として **現行 v1.0.0 が実用上の天井に近く、単純な改良では精度・回収率とも向上しない**ことが判明。

## 前提（確認済み）
- 学習データは**ローカルDB(kbar)に161万件（1986〜2021年）揃っている**。
  データ量の問題ではない。`race_entries.finish_position IS NOT NULL` で取得。
- 時系列分割: train < 2020（約150万）／ test >= 2020（約7.7万・5585レース）。
- 学習: `make train version=vX cutoff=2020` または
  `uv run python -m app.pipeline.cli train --version vX --cutoff 2020`。
- 現行モデル v1.0.0 は **binary分類（target=is_place 複勝圏内）**、特徴量約35＋カテゴリ6。

## ベースライン（v1.0.0・2020-2021の5585レースで実測）
| 指標 | 値 |
|------|----|
| ROC-AUC | 0.8115 |
| 単勝的中(◎が1着) | 32.34% |
| ◎が3着内 | 63.87% |
| 複勝的中(上位3予想が3着内) | 52.45% |

## 試した改良と結果（すべて本番不採用）

### 1. レース内相対順位の特徴量追加（within-race relative rank）
- 8特徴量（近走着順/勝率/賞金/斤量/オッズ等のレース内パーセンタイル順位）を追加。
- 結果: AUC 0.8117、単勝32.37%、複勝52.52% → **ほぼ変化なし**。
- 理由: 既存の `win_favorite`（人気順）等と冗長。木モデルは相対比較を部分的に学習済み。

### 2. LambdaRank（順位学習）化
- objective=lambdarank、relevance=着順グレード、group=レース単位、metric=ndcg。
- 結果: 単勝32.39%、複勝52.46% → **ほぼ変化なし**。AUCは僅かに低下(0.8080)。
- 理由: 精度の天井は**損失関数でなく特徴量の情報量**で決まる。

### 3. 回収率志向の妙味モデル（オッズ非依存win確率 → EV → ROI）
- オッズ(win_odds/win_favorite)を**入力から外した**win確率モデルを学習。
- EV = p_win × 単勝オッズ − 1 で妙味馬を抽出し、EV閾値別に回収率を実測。

| 戦略 | 的中 | ROI |
|------|------|-----|
| 全馬 | 7.25% | 75.6% |
| 1番人気 | 32.7% | **80.1%**（最良） |
| AI(非依存)1位 | 23.0% | 72.2% |
| EV>0 | 2.38% | 71.4%（平均98倍の人気薄に集中） |
| EV>0 & 1-5倍帯 | 20.7% | 85.6%（最良セグメントでも100%未満） |

- 結果: **どの戦略・セグメントも ROI 100%未満**。EV戦略は穴馬の勝率過大評価で
  大負け（大穴バイアスの罠）。オッズ非依存モデルは市場より弱い。

## 結論と次の打ち手
1. **的中率**: 現行モデルは実質的に**市場（オッズ・人気）のランキングを再現**しており、
   同じ情報では市場を超えられない＝頭打ち。v1.0.0で十分。
2. **回収率**: 単純な妙味戦略では**控除率(約20%)に勝てない**。市場は効率的。
3. **唯一の現実的な改善方向＝レバーA**: 市場が完全には織り込めない**新情報を現在レースでも取得**する。
   - 過去データは `corner_pos_1..4`（脚質/コーナー通過順）が100%入っているが、
     **直近スクレイプは0%**（2025は41.8%、2026は0%）。`odds_snapshots`（オッズ時系列）も直近のみ。
   - **スクレイパーを改修して脚質・展開・オッズ変動を現在レースでも取得**すれば特徴量化できる。
     ただし控除率超えは業界的にも難関で、payoffは不確実。
4. それ以外は方針書どおり「1年使い込んで実績を貯めてから再判断」が妥当。
